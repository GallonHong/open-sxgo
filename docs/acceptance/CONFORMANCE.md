# TUF 兼容性与浏览器差分

官方测试套件版本：2.5.0，Git commit `601f45680111cb3f90008dd878b60fc5de4e542a`。测试在隔离 Linux 容器中运行，Node 24/WebCrypto；详细测试名称及结果保存在 `conformance.json`。

共用验证核心：**116 passed，3 个可选 ML-DSA 算法用例不支持**。在 `scripts/conformance/client.xfails` 显式列出可选算法族；没有隐藏其他失败。覆盖签名阈值、重复签名、根恢复、过期、缓存、快进/回滚、委派 DFS、终止路径、摘要、异常角色名称和静态资料库。

官方 `tuf-js 6.0.0` 对照运行：112 passed，7 failed，其中 6 个为扩展算法，另一个为缓存子角色针对不同委派父级重新授权的用例。项目自己实现的该用例通过；生产发布仍使用平面 Targets，并叠加独立业务签名验证。这里记录的是本次套件结果，不将官方包名等同于验收通过。

浏览器差分：在 Chromium、Firefox、WebKit 中分别将同一虚构包执行有效、篡改、到期、回滚、分叉和不足签名测试，与 Node 核心结果比较，18 项一致。这不是把全部 119 项套件在三个浏览器中重跑；真实浏览器覆盖边界应保留。

套件入口为 `scripts/conformance/client`，以 `WFD_CONFORMANCE_CLIENT=official` 选择官方对照，否则使用项目核心。Docker 构建文件在同目录，正常工程上下文不包含 `.runtime`，需要创建只含公开源码和指定上游测试源码的临时构建上下文。不要把完整工作目录或私密数据作为套件输入。

测试通过不消除所有实现风险。生产前仍需验证更新失败后的可信状态检查点、真正断电恢复、不同版本历史追赶、目标云环境和独立人员的操作记录。
