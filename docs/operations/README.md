## 上线门槛

全部门槛均需记录责任人、依据、日期、版本和复核人。当前没有生产批准记录，不能把代码中的布尔值当作治理证据。

| ------------------ | -------------------------------------------- |
| GATE-01 运营责任   | 运营主体、地区和适用性审查待落实             |
| GATE-02 产品表述   | 演示范围/未知/制度文案可检查，真实内容待复核 |

## 监控与周期任务

Worker 定时任务清理到期私密内容与限流计数。后台提供积压数量、最旧工单、公开条件到期提醒；镜像 `/health` 提供当前副本。真实供应商额度、异常增长、独立镜像新鲜度和人员排班的告警尚未接入，不能据此开放无限投稿。

每次发布前对比两个独立运营/供应商副本中的同一签名头；发现同纪元同序号不同摘要，立即暂停自动跟随并保存公开证据。不同域名共享一个账号不算独立。切换失败保留完整旧快照，客户端显示历史状态。

## 公共恢复

运行 README 中的恢复命令生成新目录及 ZIP。工具只复制验证器消费的元数据和清单文件；检查目录不含私钥、回执、投稿或内部记录。将归档和可信根指纹经两个独立渠道交给独立机器，独立验证全部文件后再服务。同步失败不得清空上一完整版本。

IPFS 手工备份仅对经过审查的公开恢复目录执行；先离线核对根与全部摘要，再由节点操作者使用已审核的 IPFS 工具添加公共文件、记录 CID 与版本，在另一个节点读取并复验。不得添加工作目录、私密 DB、密钥或投稿材料。尚未执行真实 IPFS 发布。

## 事件处理

- 隐私误发：停发相关包、暂停推荐，隔离误发内容与访问权限；从受控当前分发源清除，通知已登记镜像清理并记录完成情况。公开记录只写事件范围和批次，不重贴敏感内容。保留必要最小内部调查信息并设到期日。
- 密钥泄漏/信任根异常：停止发布和自动跟随，独立核对受影响角色，由离线根持有人执行规范轮换；不能靠更换域名恢复信任。必要时通过既有可信渠道分发新引导根并解释旧历史边界。
- 分叉：保留两个签名头供核查，不按多数镜像投票选“真头”；治理解决之前显示旧历史、关闭推荐。
- 钓鱼或主体关系失效：签名暂停相应范围/链接，恢复必须复核和新发布。仅 HTTP 可访问不能维持推荐资格。

真实联系人、通知渠道和演练责任人尚未登记。未登记前保持封闭演示；本次没有向外部发送任何通知。
