## 已有实现与证据

- 三个独立 React/Vite 构建，公开页面使用虚构数据，匿名投稿与管理员会话分开；公共 Service Worker 不缓存私密路径。
- Hono/Drizzle、SQLite 与 D1 适配，同一业务契约在 SQLite 与 Miniflare D1 上执行，验证事务回滚、并发冲突、双人复核和权限。
- Better Auth 邀请制密码/TOTP：真实库集成测试验证初始绑定、再次登录的第二因素；没有把演示身份当成真实独立人员登记。
- 严格公开 Schema、范围与未知状态、来源家族、规则有效期；构建 JSON、JSONL、SQLite、分片及摘要清单。
- 发布业务签名验证、Root/Targets 阈值、旧/新根双阈值轮换检查、过期/回滚/分叉阻断；CLI 同时运行官方 `tuf-js`。浏览器与 Node 共用核心的**官方套件 116 项通过，3 项可选 ML-DSA 不支持；三浏览器 18 项差分断言通过**。
- 公开构建分发器在两份完整读回之前不切换 timestamp；提供文件系统/R2 适配。R2 适配尚未在真实云资源上验收。签名暂停清单的恢复要求发布绑定与 Targets 阈值。
- Docker 只读镜像已实际启动并通过官方客户端验证；公开恢复包使用消费过的验证文件白名单，不复制未知文件。
- 当前 85 项单元/集成测试通过；三种浏览器 18 项流程通过；安装版断网重载通过。后续变动以最新运行报告为准。
- 十万条范围索引基准在本机测得 gzip 2,154,562 字节、查询 P95 约 255 ms。该结果不代表普通手机、不代表完整数据下载时延。

## 不得作为上线完成证明的限制

1. `production_release_enabled` 和推广在服务端保持关闭，发布端点返回 `PRODUCTION_GATE_CLOSED`。不能仅设置环境变量就跳过门槛。
2. 本地邀请脚本可以创建多个演示人员编号，不能证明真实人员独立。生产需独立登记及授权人确认。
3. WFD 发布采用 Ed25519、SHA-256 和一致快照；共用 TUF 核心已覆盖委派遍历、RSA/ECDSA 和 SHA-512 兼容测试，不支持 ML-DSA。已增加最多 64 版的逐摘要历史追赶和历史分发检查；长时间中断与独立恢复仍需演练。
4. Mirror 健康接口报告可服务的副本，不等同于实时数据仍有效；客户端会检查元数据期限。当前未实现自动选择多个备用节点。
5. 私密数据的到期清理针对主库记录与对话；真实数据库备份、供应商日志、人工设备副本的删除与保全仍须部署侧演练。
6. 链接检查器在应用层固定已校验 IP，生产还需网络层出口限制、逐跳集成测试、平台精确店铺标识验证和人工复核，不能仅依靠域名或 HTTP 200。
7. 公开隐私扫描是保守的诱饵/格式阻断，不能发现所有可再识别信息，必须人工复核。
8. 无法对被替换的网页与其根公钥进行网页内自证；应通过可信发行渠道核对客户端与根指纹。
